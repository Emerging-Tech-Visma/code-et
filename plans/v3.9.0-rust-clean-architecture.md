# code-et v3.9.0 — Pure-Rust Clean Architecture Bootstrap + CI Gate

## Context

**Why this change.** code-et today is a workflow planner (`/code:go`, `/code:grill`, `/code:prd`, `/code:plan-issue`, `/code:implement`). It has no opinions on project structure, no doctrine, no enforcement. The user reports two recurring failures: **security misses at boundaries** and **AI slop accumulating** (dead code, unused crates, duplicated logic, defensive over-programming, mirror tests, architecture drift).

**Outcome.** Make code-et a **pure-Rust Clean Architecture** plugin. v3.9.0 lands three pillars:

1. **Doctrine** (`docs/`) — Rust Clean Architecture, anti-slop framework, per-layer testing matrix.
2. **Bootstrap** (`/code:bootstrap`) — scaffolds **one** project shape: `axum + sqlx + dioxus + tokio` full-stack. Dioxus 0.7+ is the *only* frontend, targeting **web, desktop, and mobile** from a single component tree via feature flags. The 4-crate workspace (`domain`, `application`, `infrastructure`, `interface`) lets `cargo`'s own dependency declarations enforce the Dependency Rule at compile time — violating imports fail at `cargo build`.
3. **CI gate** (`.github/workflows/code-et-audit.yml`) — every PR runs `cargo fmt --check`, `cargo clippy -D warnings`, `cargo machete`, `cargo audit`, `cargo deny check`, `cargo nextest`, and a 30-line layer-deps validator. Authoritative enforcement layer.

**`CLAUDE.md` is the lean control plane** (≤ 12 added lines). The plugin's own CLAUDE.md is also re-flavoured Rust: `cargo nextest run && cargo clippy --all-targets -D warnings` replaces the leftover `bun test` example; "TypeScript strict mode" / "server components by default" are removed.

**Audit (`/code:audit`)** is deferred to v3.10.0 as a local preview that mirrors the CI gate 1:1, reusing bootstrap output as fixtures.

**Decisions baked in (from user input):**
- **Rust 100%.** No TypeScript path. **Tauri removed entirely** — Dioxus 0.7+ covers desktop, web, and mobile from one Rust UI codebase.
- **Dioxus 0.7+ is the only frontend** in every doctrine, template, and skill. Existing user projects on Tauri+Svelte (`speech`, `clean-up`) keep their stack; the new doctrine doesn't try to retrofit them.
- **Database:** PostgreSQL on **GCP Cloud SQL** for production; **SQLite** for local. `sqlx` with compile-time `query!` macros and `sqlx::migrate!` (forward-only). Same migration directory works for both engines.
- **Hard-depend on `knowledge-work-plugins/engineering`** for human-judgment skills (`code-review`, `tech-debt`, `testing-strategy`, `system-design`). CLAUDE.md tells Claude when to invoke them with Clean Architecture context.
- **Replace `typescript-lsp` companion with `rust-analyzer-lsp`** (verified: official marketplace ships it; `rust-analyzer 1.93.1` already on the user's machine). `/code:plan-issue` keeps using LSP for `documentSymbol`/`findReferences`/`definition` — same protocol, Rust-language now.
- **GitHub Actions CI is the strongest gate.** Local hooks remain for fast feedback; CI blocks merges.
- **Minimum viable audit (deferred to v3.10.0).** No Tarjan SCC, no jscpd duplication engine, no custom cognitive-complexity gating — `cargo`'s own dependency rules + `clippy.toml` thresholds do 80% of the work for ~20% of the code.
- **Bootstrap installs are opt-in** (print-checklist by default; `--install-tools` to opt in).

**Existing hooks audited and kept as-is** (no changes needed beyond one extension):
- `auto-approve-readonly.sh` — language-agnostic. Allows `Read|Grep|Glob|LSP`. **Works for `rust-analyzer-lsp` unchanged.**
- `verify-gate.sh` → `run-tests.sh` — `run-tests.sh` already detects `Cargo.toml` and runs `cargo test`. **No edit needed**, though we'll switch the documented example to `cargo nextest run`.
- `task-created-tag-check.sh` — **extend** to require `metadata.layer ∈ {domain, application, infrastructure, interface, chore}`.

- Engineering plugin (`knowledge-work-plugins/engineering`) — already on user's machine; provides skills CLAUDE.md delegates to.
- `rust-analyzer-lsp` (official marketplace) — Rust LSP companion.
- Memory invariants: minimal commands; reject hardcoded app names; never bump only `plugin.json` or only `CHANGELOG.md`.

## Recommended Approach

### Layer A — Doctrine (`code-et-implementer/docs/`)

Three short Rust-only markdown files. Loaded on demand by `/code:bootstrap`, `/code:go`, `/code:plan-issue`, `/code:implement`. Each file ≤ 200 lines, action-oriented. Doctrine is the **delta** over the engineering plugin, not a replacement.

| File | Owns | Delegates (via CLAUDE.md) |
|---|---|---|
| `architecture.md` | **Rust Clean Architecture** for the single shape: `axum + sqlx + dioxus + tokio` full-stack. Concrete folder map. The Dependency Rule + how `Cargo.toml` workspace deps *enforce* it (compiler-level, not lint). DTO crossing rule. DIP via traits in `application` implemented in `infrastructure`. **Frontend section**: Dioxus 0.7+ for web/desktop/mobile from one component tree (feature flags `dioxus-web`, `dioxus-desktop`, `dioxus-mobile`); `dioxus-fullstack` for SSR + client islands wired through axum. **Database section**: Postgres-on-GCP-Cloud-SQL (Cloud SQL Proxy + IAM auth, pool sizing, forward-only migrations, recovery script per migration), SQLite for local; same migrations dir. **Secrets baseline**: GCP Secret Manager for prod, `dotenvy` for local only, never commit secrets. **Rust security checklist**: `unsafe` blocks rationale + audit, `serde` deserialization of untrusted input, `sqlx::query!` over raw `query`, FFI boundaries. Includes Uncle Bob's excerpt verbatim. | engineering's `system-design` for ADR/trade-off framing. |
| `anti-slop.md` | The 4-element framework (dead code & deps, duplication, complexity hotspots, architecture drift). The 5 slop categories (Superficial Competence, Unnecessary Complexity, Defensive Over-Programming, Mirror Tests, Inconsistent Styling). Per-category "how to detect" + "how to fix". The 4-stage verification loop the CI workflow executes (and v3.10.0's `/code:audit` will mirror). | engineering's `tech-debt` for prioritization (Impact × Risk × Effort). |
| `testing.md` | **Per-layer test matrix**: `domain` = pure unit (in-module `#[cfg(test)]`); `application` = use-case tests with `mockall` fakes for ports; `infrastructure` = integration via `sqlx::test` (Postgres in CI service container, SQLite for unit); `interface` = e2e via `axum-test` for HTTP, **`dioxus-testing` for UI components** (web/desktop/mobile — single test tree). **Mirror-test ban.** Contract tests at every boundary. Security test cases (auth, input validation, parameter-bound queries). `cargo-nextest` as the runner. | engineering's `testing-strategy` for the pyramid + general what-to-cover. |

### Layer B — Bootstrap skill (`code-et-implementer/commands/bootstrap.md`)

Single new command, ≤ 130 lines, frontmatter `effort: xhigh`. Interactive scaffolder for new pure-Rust projects.

**Flow:**
1. Detect or ask: project name (validated, no Visma-only assumptions), database (`sqlite` default | `postgres`), targets (any subset of `{web, desktop, mobile}`; default = all three).
2. Refuse to run if CWD has `Cargo.toml` or `package.json` unless `--force`.
3. Copy template from `templates/rust/dioxus-fullstack/`; substitute `{{name}}`, `{{db}}`, `{{targets}}` placeholders. Targets become Cargo features on the `interface` crate.
4. Run `cargo new --workspace .` only when scaffolding into an empty dir; otherwise pure file-copy.
5. Print install checklist: `cargo install` lines for `dioxus-cli`, `cargo-machete`, `cargo-audit`, `cargo-deny`, `cargo-nextest`, `sqlx-cli`, optional `cargo-udeps`. With `--install-tools`, run them.
6. Seed project's `CLAUDE.md` from `templates/shared/CLAUDE.md.template`, pointing at the plugin's doctrine and naming `rust-analyzer-lsp` + engineering plugin as recommended companions.
7. Run `cargo check --workspace --all-features` once to verify the skeleton compiles.
8. Print next steps: `cd <name> && /code:grill` (feature lane) or `/code:go` (bug lane). Recommend `gh repo create` + push to enable the CI gate immediately.

### Layer C — Template (`code-et-implementer/templates/rust/dioxus-fullstack/`)

**One template only.** Pure Rust full-stack. All Dioxus, no Tauri.

```
templates/
  rust/
    dioxus-fullstack/
      Cargo.toml                       # workspace declares 4 layer crates + apps/*
      crates/
        domain/                        # entities, value objects, errors
          Cargo.toml                   # deps: serde, thiserror, uuid, time. NO workspace deps.
          src/lib.rs                   # module skeleton + one example entity
        application/                   # use cases + ports (traits)
          Cargo.toml                   # deps: domain only. async-trait, anyhow.
          src/lib.rs                   # one example use case + one port trait
        infrastructure/                # adapters
          Cargo.toml                   # deps: application, domain. sqlx, reqwest, tokio.
          src/{lib.rs, repos/, http/, config/}
        interface/                     # dioxus components + axum handlers (composition lives in apps/)
          Cargo.toml                   # deps: application, domain. dioxus, axum, tower.
                                       # Features: web, desktop, mobile (gate render targets)
          src/{lib.rs, components/, http/}
      apps/
        server/                        # bin: axum + dioxus-fullstack SSR
          Cargo.toml
          src/main.rs                  # composes infrastructure into interface ports
        desktop/                       # bin: dioxus-desktop renderer (uses interface::components)
          Cargo.toml                   # depends on interface (feature = "desktop")
          src/main.rs
        web/                           # bin: dioxus-web (WASM)
          Cargo.toml                   # depends on interface (feature = "web")
          src/main.rs
        mobile/                        # bin: dioxus-mobile (iOS + Android)
          Cargo.toml                   # depends on interface (feature = "mobile")
          src/main.rs
                                       # Apps share interface/components — write the UI once.
      migrations/                      # sqlx::migrate! source. SQLite + Postgres compatible.
        20250101000000_init.sql
      .github/workflows/code-et-audit.yml
      .env.example                     # DATABASE_URL=sqlite:./dev.db (toggle to postgres://)
      .gitignore
      .editorconfig
      clippy.toml                      # cognitive_complexity threshold; deny list
      deny.toml                        # cargo-deny config
      rust-toolchain.toml              # stable + nightly component for udeps (opt-in)
      Dioxus.toml                      # dioxus-cli config
      justfile                         # check, test, fmt, lint, audit, db:migrate,
                                       # run:server, run:desktop, run:web, run:mobile
      sqlx-data.json                   # placeholder for offline mode
      CLAUDE.md                        # project-specific, points at plugin doctrine
      README.md                        # quick-start + layer rules + Dioxus build matrix
  shared/
    CLAUDE.md.template                 # copied to project root, references plugin doctrine + companions
    layer-deps-validator.sh            # 30-line bash: parse each crate's [dependencies], assert inward rule
    UPDATING.md                        # checklist for updating templates when axum/dioxus minor versions move
```

The four user-facing apps (`server`, `desktop`, `web`, `mobile`) each have one `main.rs` that composes `infrastructure` + `interface` for their target. **The UI is written once in `interface::components`** and rendered everywhere.

### Layer D — CI workflow (`templates/shared/.github/workflows/code-et-audit.yml`)

Authoritative enforcement layer. Runs on every PR + push to main.

```yaml
name: code-et-audit
on:
  pull_request:
  push:
    branches: [main]
jobs:
  audit:
    runs-on: ubuntu-latest
    services:
      postgres:                          # Used when DATABASE_URL targets postgres in tests
        image: postgres:16
        env: { POSTGRES_PASSWORD: postgres }
        ports: ['5432:5432']
        options: --health-cmd pg_isready --health-interval 10s
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
        with: { components: 'rustfmt, clippy' }
      - uses: Swatinem/rust-cache@v2
      - name: fmt
        run: cargo fmt --all -- --check
      - name: clippy (deny warnings)
        run: cargo clippy --workspace --all-targets --all-features -- -D warnings
      - name: layer-deps validator
        run: bash scripts/layer-deps-validator.sh
      - name: cargo-machete (unused deps)
        uses: bnjbvr/cargo-machete@main
      - name: cargo-audit (advisories)
        uses: rustsec/audit-check@v1
      - name: cargo-deny (license + bans)
        uses: EmbarkStudios/cargo-deny-action@v1
      - name: tests
        run: cargo nextest run --workspace
        env:
          DATABASE_URL: sqlite::memory:
```

**`scripts/layer-deps-validator.sh`** (30 lines, shipped in template) reads each crate's `[dependencies]` and asserts the inward rule (`domain` → none; `application` → only `domain`; `infrastructure`/`interface` → may depend on inner layers, never outer). Replaces the originally-planned Tarjan SCC.

**`/code:install-ci`** (≤ 40 lines) copies this workflow + the validator into an existing Rust repo, for projects that pre-date the bootstrap.

**2. Add a new section, ≤ 12 lines:**

```
## Clean Architecture (Rust) — controlling rules

When operating on a Rust project, apply Clean Architecture per
docs/architecture.md. Each new or modified file declares its layer
(domain | application | infrastructure | interface | chore) in
metadata.layer. Imports point inward; the Cargo.toml workspace deps
already enforce this — violating imports fail at cargo build.

UI: Dioxus 0.7+ for web, desktop, and mobile from one component tree.
DB: Postgres on GCP Cloud SQL for prod, SQLite for local. sqlx with
query! (compile-time-checked); never raw SQL. Forward-only migrations.

Delegation map for human-judgment passes:
- security/code review → engineering plugin's code-review skill
- testing strategy   → engineering plugin's testing-strategy skill
- tech-debt triage    → engineering plugin's tech-debt skill
- ADR / system design → engineering plugin's system-design skill or /architecture
- LSP precision       → rust-analyzer-lsp companion plugin

Anti-slop hard rules: see docs/anti-slop.md. Rule of Three. No mirror
tests. No defensive validation at trusted boundaries.
```

Substance lives in `docs/`. CLAUDE.md is pointers + delegation map.
